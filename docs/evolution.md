# Harness 自进化：内循环、外循环与两类积累

ecogym 0.2.0 · 本文说明 `episodes/`（内循环）、`evolution/`（外循环）、`task/suite.py`（任务组）、`evaluation/suite.py`（多任务比较）和 `episodes/export.py`（训练数据）的设计与用法。

## 1. 一句话

给一组生态预测任务和数据，DSH 研究智能体按某一版 Harness 独立解每个任务；评审智能体根据隐藏期成绩和完整轨迹提出新的 Harness 候选；候选只有在多任务配对比较中可信地变好才被继承，被采纳的版本再在留出任务和封存时期上各验证一次。过程中积累知识（技能、代码库、经验、专家意见）和轨迹（每次模型请求与回复、工具调用、代码与成绩），后者可以导出为多轮 SFT 数据和偏好对。

DSH 内核不改：进化的只是 DSH 能加载的内容（指令、技能、代码库、经验、少数 DSH 设置）；打分由确定性的宿主代码完成，不交给 LLM。

## 2. 内循环：一个回合

`ecogym episode run TASK [--harness H]`，代码在 `episodes/runner.py`、`episodes/agent.py`。

| 步骤 | 内容 |
|---|---|
| 工作区 | `TASK.md`（目标、评分、接口、时限、预算）、`AGENTS.md`（Harness 的指令加经验）、`data/`（隐藏期之前的可见数据、列说明、背景、专家意见 `expert.md`）、`submission/`（Harness 的起始代码）。技能放在 DSH 的技能目录。 |
| 会话 | `dsh --profile headless` 在 macOS 沙箱里运行：只能读写自己的回合目录，只能连本机的模型网关和工具服务。网关持有真实密钥，只转发这个会话自己那个提供方的 chat completions 和 DeepSeek 的网页搜索（其他路径返回 403），按成本计 token（命中缓存的输入按 1/10），到预算或截止时间就拒绝调用，并记录每次请求和拼装好的回复。每个会话用回合目录里自己的 DSH 主目录，会话记录在回合结束后存进轨迹（`dsh_sessions.jsonl.gz`）后随回合目录删除，不进入用户 DSH 的会话列表，DSH 网页端不会加载它们。 |
| 续跑 | 智能体常常远没到时限就宣布完成（2026-10-29 的运行里 8 分钟的回合多数 1–4 分钟就结束）。结束时剩余时间超过四分之一的，宿主在同一工作区里开一段新会话（最多 3 段），告诉它剩余时间、当前以哪次提交为准和上一段的最终回复，请它继续改进；一段续跑既没有本地检验也没有提交时不再续跑（智能体认为已经做完，再开多半只是重复最终报告；数据见第 11 节）。所有版本一视同仁，不影响比较。 |
| 模型 | 写成 `<提供方>/<模型>`：`deepseek-official`（DeepSeek 官方接口），或 DSH 设置里 `llm-pi-ai.providers` 的任一提供方，例如 `pjlab/glm-5.3`；裸的 DeepSeek 模型 id 等于 `deepseek-official/<id>`。会话里的 DSH 只知道这一个提供方，地址指向本机网关；网关转发到它真实的 `baseURL`，带上 `apiKeyEnv` 指向的密钥（环境变量或 DSH 的凭据库）和设置里的 `headers`。目前支持 `openai-completions` 接口（回复能拼装进轨迹）。网页搜索走 DeepSeek 的接口，没有 `DEEPSEEK_API_KEY` 时关闭。`ecogym models` 列出全部提供方和不能用的原因。设置里列出的模型不一定能用（密钥可能无权调用），所以开始运行前宿主对每个模型发一个很小的流式请求，返回 401/403/404 就拒绝开始；面板在选中模型时做同样的测试。 |
| 工具 | `task_info`、`evaluate_local`（按裁判协议在 calibration_uq 上运行）、`submit`、`note`（finding / lesson / dead_end）、`ask_expert`（不等待回答）。 |
| 打分 | 裁判用隐藏期之前的全部行拟合最后一次被接受的提交，再逐时间步送入 model_selection 的观测，在每个计分起点要求预报；技能、缺失按 −1、物理范围裁剪、按天自助区间都沿用 Bench 的规则。预测保存为 `scored.npz`，以后的比较都从记录重算。 |
| 状态 | `finished`、`timeout`（到截止时间被终止，提交照常评分）、`infra_failed`（没有任何一次模型调用得到回复：服务故障而不是方法效果）、`interrupted`（被中断，先记账再抛出）。 |

`<任务卡>:<时段>` 表示同一张任务卡用在数据集的另一个时段（站点、团队）上，例如 `greenhouse.agc2018.cucumber.climate@1:DeepGreens`。日历切点在数据集全部非外部时段上统一计算，所以各时段的分区时间一致。

## 3. 外循环：进化 Harness

`ecogym evolve run --suite S`，代码在 `evolution/loop.py`、`evolution/evolver.py`、`evolution/evidence.py`。

```
第 0 代   起点 Harness 在每个训练任务上跑 R 个回合（基线）
第 g 代   固定本代的专家意见 → 评审会话：读证据 → 写 K 个候选 → 宿主检查
          候选与在任版本在每个训练任务上各跑 R 个回合（按任务交替排队，预算和专家意见相同）
          每个候选 vs 在任：多任务配对比较（Bonferroni 调整）
          通过者中增益最大的一个成为新的在任版本（这一代结束时生效）
```

**评审会话**是一个 DSH 智能体，工作区里有：在任版本的副本和 K 个可编辑的候选目录、本代说明 `EVOLVE.md`、固定的工作方式 `AGENTS.md`（宿主所有，不进化），以及证据目录：

- `overview.md`：各版本在各训练任务上的隐藏期成绩（含回合间的最小–最大）、在任版本的逐格技能、上一代的比较；
- `archive.md`：以往每个候选的摘要、改动文件、提案节选、结果和原因，以及评审员记下的经验（失败的候选也在这里）；
- `lessons.md`：内循环智能体在各回合记下的发现、经验和无效方向；
- `expert.md`：专家的提示和回答；
- `episodes/<回合>/summary.md` 和 `submission/`：每个回合的成绩表、本地检验与提交的时间线、笔记、工具使用、错误、最终回复和被评分的代码。

评审员能改的内容：`instructions.md`、`skills/`、`template/`（起始代码和 `ecotk/` 代码库）、`memory/lessons.md`、`harness.toml` 的 `summary` 和 `[agent]`（`model`、`reasoning_effort`、`web_search`、`subagent_depth`、`parallel_tool_calls`）。工具 `check_candidate` 按宿主的规则检查候选。会话结束后宿主自己再检查一遍：不跟随链接复制目录，写入 `name`、`parent`、`author`，加载并计算摘要，拒绝含有训练任务专有名称的文件（团队名、数据集或任务 id，以及 id 中字母和数字混合的部分，例如 `agc2018`；普通词和年份不算），相对在任版本计算逐文件 diff，模板代码改动时在一个训练任务的本地检验期上实际运行模板程序；运行没有固定内循环模型而候选改了 `[agent].model` 时，检查这个模型的提供方和密钥并发一个很小的请求（每次运行每个模型只测一次），不能调用的候选不运行，免得它的回合全部记为服务故障。只有通过检查、并且内容与在任版本和以往比较过的候选都不同的候选才会运行；比较内容时不计 `harness.toml` 的名称、来源和摘要（宿主写入或只作说明），所以换个名字重提同样的内容、只改摘要、退回起点版本都会被识别为重复。

**在任版本的成绩**只用它作为在任时跑的回合：让它被采纳的那批回合是筛选过的，计入会高估它。在任版本每一代都重新运行，回合越积越多，估计越来越准。还有一个方向相反、较弱的偏差：在任版本能一直留下来，是因为它以前的回合没有输给候选，这些回合略偏高，候选面对的基线因此略严，回合越多影响越小。

**专家意见按代固定**：每一代开始时记下账本当时的最后序号（`round_started.expert_until`）和每个训练任务的意见摘要。这一代所有回合读到同一份意见，之后到的回答从下一代起生效；在任版本以前的回合只有在同一份意见下跑的才计入比较，意见变了就只用本代同时跑的在任回合。回合队列按任务交替排列（同一任务上先后是在任、候选 a、候选 b……），没有哪个版本整体排在后面。

**服务不可用时停下**：一代的全部回合（重试之后）或评审会话都没有得到任何模型回复时，运行停下并记为失败，错误里带着提供方的回答（例如 403 model_not_available）；不再空转完剩下的代。修好提供方后可以继续运行。

**可恢复**：外循环的全部状态（在任版本、它的无偏回合、比较过的版本）在每一代开始时从账本重新计算，`ecogym evolve run --resume RUN` 从最后一个完成的代继续。采纳在这一代结束（`round_finished`）时才生效：在 `harness_adopted` 之后、这一代结束之前中断的话，重跑这一代时仍用原来的在任版本。每一代记下运行它的进程（`owner`：pid 与主机名）；账本显示运行中而这个进程已经不在时，面板直接显示“已中断”，可以继续。

## 4. 多任务配对比较

代码在 `evaluation/suite.py`，门槛写在任务组的 `[gates]` 里。

- 每个任务：增益 = 候选各回合目标值的均值 − 在任各回合的均值；区间由按天的块自助给出，同时重抽回合。
- 整个任务组：增益 = 各任务增益的均值。3 个及以上任务时，区间是各任务增益的 t 区间：均值 ± t(N−1)·s/√N（决定里记为 `basis: "tasks_t"`）。每个任务的增益已经带着回合间的随机差异，任务间的差异进入 s。只有几个任务时，对任务做自助会把区间算窄：方差只有样本方差的 (N−1)/N，分位数接近正态而不是 t₃。在 4 个任务、任务间差异大于任务内噪声的模拟中，旧的自助法让零增益的候选以名义值 2–3 倍的比例被采纳；t 区间在任务相互独立时与名义值一致（2.5% 对 2.48%，20 万次）。
- 少于 3 个任务时无法估计任务间的差异，区间依次重抽任务、回合和天（`basis: "bootstrap"`），同一数据集的任务共用天的抽样，因为它们共享天气和日历。这时区间只反映任务内的随机差异，不算真正的检验。抽样次数至少保证区间端点之外还有 10 次抽样（`resamples` 不够时自动增加）。
- 采纳需要同时满足：平均增益大于 `min_delta`（默认 0.005）；区间下限大于 0；没有任务的损失超过 `task_cap`（默认 0.03）且它自己的区间整体低于 0。区间是双侧的 `confidence`（默认 95%），只看下限，所以这是单侧 2.5% 的检验；K 个候选时任务组区间的置信度按 Bonferroni 调整为 1 − 0.05/K（单侧 2.5%/K）。单任务的区间固定用 `confidence`，不随 K 放宽否决。某个训练任务没有可用回合（例如重试后仍是服务故障）的候选这一代不采纳。
- t 区间把同一数据集的两个隔间当成独立的任务，但它们共享天气。默认任务组是两个数据集各两个隔间；同数据集任务的增益相关系数为 0.5 时，模拟中的误采纳率约为名义值的 2 倍（旧的自助法 4–6 倍）。加入更多数据集能缓解，按数据集聚类在只有两个数据集时检验力太低，没有采用。
- 单任务否决要求两个版本在该任务上都至少有 2 个回合。单任务的区间只重抽天和回合，候选只有 1 个回合时不含它回合间的随机差异，一次运气不好的运行就会被当成可信的损失：2026-10-29 的网页端运行里，两个候选都因为同一个任务上的单次回合被否决（−0.069、−0.036），而同一任务上在任版本两个回合本身就差 0.048。这样的任务记为 `unconfirmed_regression`，不否决。每个版本每个任务只跑 1 个回合（`repeats = 1`）时，否决因此不起作用，只剩任务组区间；正式运行建议 `repeats ≥ 2`。
- 面板的成绩表和评审员的 `overview.md` 另外给出“平均各回合的预报”：同一版本在同一任务上几个回合的隐藏期预报逐时刻平均后的总分（`evolution/ensemble.py`），面板还给出全部回合一起平均的总分。只用每个起点都有预报的回合（缺预报的回合不计入，并注明个数），所以平均后的提高不会来自用别的回合填补缺口。它只作参考，不进入门槛：门槛衡量一个智能体用这版 Harness 能做到什么，SFT 数据需要的也是这个。数据见第 12 节。

## 5. 独立验证

代码在 `evolution/verify.py`，结果写在进化运行的账本里。

- `ecogym evolve verify RUN --holdout`：起点版本和最终版本在任务组的留出任务（评审员看不到）上各跑一个回合，比较最终 − 起点。每个（版本，任务）的曝光在它的回合即将开始时登记（排队的回合还没有登记），所以登记过的曝光几秒内就有回合；另一个验证看到“已登记、还没有回合、登记不到 10 分钟”或“回合正在运行”时不会重复运行。同一版本以后再验证时复用已有回合。因服务故障或中断而没有成绩的曝光可以重跑：结果不完整时再次验证这次运行只补这些任务（面板里的「补跑」），然后记下新的结果。服务一次只运行一个验证。
- `ecogym evolve verify RUN --sealed validation`（之后才能 `final_test`）：把两个版本提交过的预测程序（训练任务上最近一次、留出任务上的那次）用封存时期之前的全部行重新拟合，逐时间步预报封存时期；每个（版本，任务，分区）只评一次。进化过程中没有任何人看过这些时期，所以它衡量的是向未来时期的迁移。每个任务评完立即记入账本（`sealed_task`）：中途中断（关闭 DSH、重启后端）后再评，只补这次运行登记过但还没有结果的任务，这些程序的成绩从未公布，重评不泄露信息。另一次运行（例如同一起点版本）已经评过同一版本、同一任务时直接复用它的结果。`final_test` 评的是 validation 评过的同一个程序。
- 两种验证的结论都用任务组的门槛（平均增益和任务组区间）。每个版本在每个任务上只有一个结果（一个回合或一个程序），区间里没有回合间的随机差异，所以不做单任务否决：单个任务上的损失记为 `unconfirmed_regression`，逐任务成绩照样列出。
- 记录里的预测文件带内容摘要（`predictions_digest`），比较和导出读取时核对；文件被改过就拒绝使用，而不是悄悄改变重算的结论。

## 6. 两类积累

**知识**：Harness 本身（技能、代码库、经验，内容寻址存放在 `$ECOGYM_HOME/harnesses/<摘要>`，`ecogym harness show / diff` 查看）、账本里的全部笔记（回合笔记与评审员笔记）、专家的提示与回答。

**轨迹**：每个回合和评审会话的 `$ECOGYM_HOME/trajectories/<会话>/` 下有 `llm_calls.jsonl.gz`（每次模型请求的完整消息、工具定义和拼装好的回复：内容、推理、工具调用、结束原因）、`dsh_sessions.jsonl.gz`（DSH 会话事件，包括子智能体）、`mcp_calls.jsonl.gz`（ecogym 工具调用）、`workspace.tar.gz`（工作区、每次检验和提交的代码快照）和 `scored.npz`（隐藏期预测）。

`ecogym export --out DIR` 把它们变成训练数据：

| 文件 | 内容 |
|---|---|
| `sft.jsonl` | 每个会话线程一条：`messages`（system、user、带推理与工具调用的 assistant、tool 结果，以模型在该线程的最后一次回复结束）、`tools`、`meta`（任务、Harness、模型、隐藏期成绩与区间、相对参考方法是否更好、来自哪次进化与哪一代、角色、被接受的提交数、`auto`）。默认只导出这样的回合：正常结束；被评分的是一次被接受的提交，而不是从未成功提交时的自动快照（`meta.auto`）；隐藏期成绩高于 `--min-score`（默认 0，即朴素基线；只改了模板就提交的回合约为 0，不收）。评审会话要至少提出一个有效候选。`--all` 导出全部，由 `meta.passes_filters` 标记。同一请求重发（流式重试）时取后一次回复，不会重复成两条样本。 |
| `preferences.jsonl` | 同一任务上两个回合的隐藏期成绩差至少 `--margin`（默认 0.02）且配对按天自助区间在 0 以上时，成绩高的为 chosen：`prompt`（第一次模型回复之前的消息）、`chosen`、`rejected`（各自其后的完整对话）。默认只配对提示完全相同的两个回合（同一版 Harness 的指令、技能和经验），这样 `rejected` 回答的确实是 `prompt`；`--cross-prompt` 也导出提示不同的对，它们多一个 `rejected_prompt`（负方自己的提示）。冒烟账本上 7 个可信拉开的对里有 2 个提示相同。 |
| `episodes.jsonl` | 每个回合一行：任务、Harness、模型、状态、成绩、轨迹位置与文件摘要。 |
| `notes.jsonl` | 全部笔记：经验库。 |
| `manifest.json` | 计数、过滤条件、跳过的原因。 |

会话目录路径（默认的 `/tmp/ecogym` 和 `$ECOGYM_SCRATCH` 下的都算，带不带 `/private` 前缀都算）统一替换为 `/workspace`；会话令牌和形如密钥的字符串替换为 `<redacted>`。真实 API 密钥从不进入轨迹：网关只记录请求体，不记录请求头。

## 7. 专家参与

智能体（内循环与评审员）用 `ask_expert` 留言后继续工作。专家随时回答（`ecogym expert list`、`ecogym expert answer ID TEXT`，或 DSH「生态进化」面板的“专家”页），也可以主动给提示（`ecogym expert note SCOPE TEXT`，范围是 `*`、数据集、任务卡或 `<任务卡>:<时段>`）。以后匹配任务的回合在 `data/expert.md` 里读到它们；评审员的证据里也有。

回答适用于提问回合所在数据集的全部任务；提问的是留出验证的回合时，回答只适用于那个留出任务，不进入训练任务的回合，也不进入评审员的证据。评审员的 `expert.md` 只含适用于训练任务的提示和回答（范围是某个留出任务的提示不会出现）。进化运行中，意见在每一代开始时固定（见第 3 节）。

## 8. 用法与成本

```bash
ecogym setup                                     # 智能体运行时（Python 科学计算环境）
ecogym suites                                    # 任务组：训练与留出任务
ecogym evolve run --suite greenhouse.climate@1 --generations 3 --candidates 2 --minutes 20
ecogym evolve show evo:…                         # 各代候选、比较和采纳
```

不算重试和重跑，一次运行有 N·R·(1 + G·(K+1)) 个回合和 G 次评审会话（N 个训练任务、R 个重复、G 代、K 个候选）。默认任务组 N = 4，R = 1、G = 3、K = 2 时是 40 个回合，并发 3 个、每个 20 分钟，约 6 小时；建议的 R = 2 是 80 个回合，约 10 小时。`greenhouse.wide.climate@1` 的 N = 8，回合数加倍。每次重试（服务故障，默认最多 1 次）多一个回合，中断后继续时那一代全部重跑，所以最坏约为两倍。冒烟测试可以用一个小任务组文件（`--suite path/to/suite.toml`）、`--model deepseek-v4-flash` 和几分钟的回合。

## 9. 已知限制

- 训练任务和同一数据集的留出任务共享天气与日历，留出任务主要检验向其他控制策略的迁移；向未来时期的迁移由封存时期检验；目前只有温室数据，还没有检验向全新生态领域的迁移。
- 每个候选需要 N·R 个回合才能比较，回合的随机差异较大，小改动很难通过门槛。增加 R 或训练任务数能提高检验力，成本线性增加。训练任务少于 3 个时比较只反映任务内的随机差异（第 4 节）。4 个训练任务时 t 区间只有 3 个自由度，只有很大且各任务一致的增益才能通过（第 11 节）；`greenhouse.wide.climate@1` 用 8 个训练隔间、2 个留出隔间，任务间差异相同时区间约窄一半。它的训练任务里有 `greenhouse.climate@1` 的 4 个留出隔间，在它上面进化出的 Harness 不要再用 `greenhouse.climate@1` 验证。
- 评审员的证据给出训练任务隐藏期（model_selection）的逐格技能，而采纳也在这一时期上比较，评审员因此可能针对这一时期调参。证据里已去掉逐格偏差（带符号，直接指出往哪边修正），隐藏期程序错误信息里的数值也被隐去；留出任务和封存时期仍是唯一独立的检验。
- 沙箱只实现了 macOS（`sandbox-exec`）。
- DSH 正常退出（Ctrl-C、关闭终端、重启后端）时，ecogym 服务在 30 秒内停下正在运行的智能体和裁判，那一代记为已停止；到时还没结束的步骤由服务记为已停止后直接退出。DSH 或服务被强制结束（`kill -9`）时，已启动的智能体进程会跑到各自的时间预算用完才退出，那一代需要在面板里「继续运行」重跑；账本里仍显示为运行中，但面板能从记录的进程号判断它已不在，显示为“已中断”。
- 一个设置文件（`~/.ecogym/dsh-plugin.json`）服务所有装了插件的 DSH profile；`ecogym dsh uninstall --profile P` 只在设置是为 P 写的时才删除它。
- 曝光登记以账本文件为单位，换账本可以绕开“只评一次”；默认所有命令共用 `$ECOGYM_HOME/ledger.sqlite3`。

## 12. 评测方案的检验（2026-10-30）

用第 11 节运行的 32 个回合在宿主上离线检验了两个问题，只读记录，不写账本。

**在可见数据里多开几个检验窗口，能不能更准地预测隐藏期？** 回合中检验或提交过的 118 个不同程序（115 个正常运行）都在可见数据末尾三个连续的 7 天窗口上按裁判协议重新运行（每个窗口用它之前的全部行拟合），再在隐藏期上评分。各任务内与隐藏期成绩的 Spearman 相关，4 个任务的平均：

| 检验 | 相关 |
|---|---|
| 现在的本地检验（calibration_uq，9.4 或 14 天） | +0.58 |
| 最近的 7 天 | +0.62 |
| 更早的两个 7 天窗口 | +0.41 |
| 三个窗口的平均 | +0.50 |

越早的窗口越不像隐藏期（季节在变：黄瓜从 9 月到 10 月，番茄从 2 月到 3 月），平均进来反而稀释了信号。在回合内部选程序（26 个回合至少有两个不同的被接受提交）：智能体最后一次提交的程序隐藏期 +0.098，按本地检验选最高的 +0.099，按三窗口平均选 +0.096，事后按隐藏期选最好的 +0.103。回合内的选择已经接近上限，所以没有加入多窗口检验；差距主要在回合之间。
