## 本轮审查发现与处理

| 问题 | 最终处理 | 证据边界 |
|---|---|---|
| 研究契约失败后，runtime/3 自动采用缺少 candidate_directions 的回退计划，提案阶段抛 TypeError | 原生运行禁止该回退，按研究契约失败明确停止；非原生回退必须显式启用 | 历史异常在数据库副本中复现，未改写原运行 |
| 模型不断使用不存在的引用或错误的修改轴/目标组合 | 实际提交给 DSH 的 Schema 绑定冻结引用，使用 oneOf 保留轴/目标/方向关系；研究综合输出上限 8192 tokens | 语义校验仍由宿主最终执行，不把结构化结果落账等同于科研计划有效 |
| 搜索计划和研究综合反复触发动态检索，增加延迟和成本 | 两阶段只使用宿主搜索流程及冻结目录；其他阶段仍按授权工具面检索 | 协调者与研究者预设分别升至 v5/v8，避免覆盖已安装不可变预设 |
| 失败、超时和取消的模型调用未计入展示用量 | 新增独立用量事件；记录运行中与结算快照，按 session 去重；允许关闭执行 admission 后结算；取消、超时或未完整结束的流不标为完整 | 只统计供应商已经报告的用量。页面显示完整覆盖数，外部检索计费、进程崩溃前未报告用量不在完整保证内 |
| 相邻 cohort 的 origin 不重叠，但预测目标时间重叠 | 新 schedule/3 按目标成熟时间隔离批次、筛选集和轮末留出集，禁止循环复用；小批次至少覆盖 24 小时 | 同批新旧版本及不同候选仍共享同一数据；适应数据作为训练材料跨代共享，不能称为每代独立训练证据 |
| 可用数据不足仍允许任意轮数 | 容量预检计算真实可行轮数，不足拒绝创建；新建默认 200 origins、50/batch、1 轮 | AiCU 的 803 行选择分区有 754 个合格 origins，默认配置可支持 1 轮 |
| 网页仍把旧分区 826 行显示为训练拟合数据 | 带冻结数据协议的请求使用四阶段视图，校验协议 digest；网页显示实际 578 行拟合数据 | UQ 校准数据和后续模型选择数据不再混入该拟合页 |
| 整批事件回放把未来累计用量用于校验过去快照，导致页面刷新失败 | 用量校验限定在当前事件之前的因果前缀；新增完整账本回放回归；真实运行无需改库即可恢复 | 不能只验证事件逐条写入，还必须验证整批重放 |
| 基线测试写死原仓库提交和 main 分支，在独立发布快照失败 | 比对当前仓库实际 Git 身份，非 Git 环境报告缺失，不把 stderr 当作提交 | 支持独立发布目录及后续分支 |
| 交付脚本遗漏新重构文档 | 完整归档和源码包纳入 docs/refactor，保留制品内容、版本、权限及隔离安装校验 | 不包含本地凭据、数据库、DSH 会话、数据归档或虚拟环境 |

## 使用与复核

1. 从完整交付包解压项目，按根目录 README 配置 Python 和 DSH；使用包内 wheel 或源码安装。
2. 供应商凭据在本地单独配置；真实 AGC 数据按 README 下载并校验。交付包不携带个人凭据和外部数据。
3. 启动后端 8777 和 DSH 8848，访问 `http://127.0.0.1:8848/plugins/ecology/evolution/`。先保留默认 1 轮，核对容量报告再增加轮数。
4. 在源码根运行 `PYTHON=<python> scripts/verify_delivery.sh --source-only`；在含制品的构建目录运行 `python scripts/verify_artifacts.py dist`。校验交付目录的 SHA256SUMS。严格的源码/制品比对要求 BUILD-INFO 对应的发布快照；原开发工作区提交不同，不能直接拿其 Git HEAD 代替发布提交。解压包无需 Git 历史即可安装运行。
5. 本次从当前已审查源码创建独立发布快照；原项目工作树和历史数据库保留。BUILD-INFO 中的提交属于发布快照，不代表替用户提交了原项目中的全部未提交改动。

## 尚未证明的能力与后续优化

- 模型研究文本仍可能把已有的独立系数拟合误写为共享系数。宿主校验保证引用、修改方向和可执行范围，不保证自由文本机制解释正确；本轮实际样例仍出现此问题。当前两个 ridge 预测器都独立拟合各目标/时距，targetwise 变体增加的是分目标/时距的残差缩放。该解释需人工复核，不能当作结构性创新证据。
- 本轮工程验收不等于全量真实供应商进化完成，更不等于跨温室或最终留出数据上的科学收益。独立最终验证、跨团队检验与目标相关不确定性仍须单独执行。
- 上一轮仅在训练拟合分区进行的 158-origin 诊断中，24h 湿度和 CO₂ 仍弱于 persistence；加长历史窗口没有普遍改善。不能将调整参数或生成候选本身宣称为性能提升，详见 `EVOLUTION-ANALYSIS-2026-09-07.md`。
- 优先补齐日/周变量的可用时间和采样频率元数据，再比较各目标/时距的正则化、残差缩放与机制增强。GreenLight、AquaCrop 等未接入的机制模型仍是研究方向。
- 原生逐起点智能体协议仍受供应商延迟影响；数值批量诊断已经可用。若新增数值批量执行模式，必须作为独立冻结协议验证，不能在已开始的运行中悄然替换逐起点智能体行为。
- 用量落账是可恢复的观察记录，尚不是供应商账单结算服务；网络长期不可用或进程崩溃时保留“不完整”状态，不显示为零消耗或完整账单。
- 大型历史模块仍可继续提取，但本次优先保证行为合同、回放与运行数据完整性。当前版本不执行模型生成的任意代码，也不控制实体温室设备。
