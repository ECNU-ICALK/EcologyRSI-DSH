# 0.3.59 网页实测、整体审查与交付说明

本版在现有工作台和事件账本上逐步修复。前端配置、后台冻结身份、原生执行、科学比较和展示共用可核对的证据；已有数据与历史交付归档保留。

## 整体框架与验收主线

本版的交付对象是可复现的本地研究闭环。主架构按“入口展示—应用编排—科学评测—运行状态—执行与存储”分工；一次运行只有宿主状态机拥有版本保留与晋级决定权。迁入的参考内核保留独立实验入口，不能与网页主链同时写冠军。

闭环依次冻结研究合同、生成四个候选、同窗初筛、对两个入围方案做局部配对，再让最终版本与原基准使用同一轮末留出样本比较，最后进行独立模型评审、反思与封存。没有合格改进时，保留原版本就是正常结果；系统不能为了“看起来在进化”放松门槛。

验收聚焦四件事：

1. **闭环完整**：研究、执行、比较、评审和结束都有真实记录，不能以开始训练或部分分数代替完成。
2. **结论可信**：双方在相同冻结样本上比较，运行失败不冒充科学收益；搜索留出不冒充独立验证。
3. **状态一致**：暂停恢复保持已封存事实，配置、实际修订、产物和网页读取同一身份。
4. **可交付**：测试绑定最终源码，源码与安装包一致，启动说明、证据和校验值齐全。

架构上的后续优先级是先在独立协议中验证降低逐时点模型调用成本，再做跨序列的等预算泛化检验；大文件拆分随明确边界逐项推进。扩展新的模型、任务或自动写代码能力不属于本次收尾范围。

## 最终评审关口的修复

对大流程的再次核对发现，旧Top-2分支在完成共同留出后直接构建最终比较，没有调用普通单候选路径中的独立模型评审，却在分析中写入评审可用。这个缺口不属于数值模型优劣问题，而是最终决策闭环缺少一个已声明的必要步骤。历史结果保留，不能补写成曾经获得独立评审。

现在先对两个入围方案的最终产物调用冻结的独立评审模型，分别写入 `EvaluationJudged`；随后以 `independent_finalist_review@1` 将实际评审身份和结果绑定到最终比较。评审只能阻止采用，不能改变科学分数、冻结样本或产物；模型接受也不能绕过科学门槛。暂时故障沿用有界重试，恢复后已完成的评审不重复调用。新决定必须具有该证据，旧的未标记决定仍按原始合同回放。

96项相关回归通过；从实际运行复制的隔离账本验证了合成拒绝回执可独立入账、产物和分数保持一致、完整重放通过。该隔离检查没有真实模型调用，不能替代原运行的最终真实评审。
