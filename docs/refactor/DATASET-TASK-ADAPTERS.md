# 数据集任务适配器

网页目前仅提供 2018 黄瓜和 2019 番茄，默认选择黄瓜。来源目录 `datasets/autonomous_greenhouse.json` 分别引用 `agc_cucumber_2018.json` 和 `agc_tomato_2019.json`。两份定义包含原始说明文件的 SHA-256、CSV 字段映射、单位、观测频率、可用时间、预测目标和评测指标。后端启动时加载并校验，构建不可变的 `DatasetAdapter`；网页、运行创建、Agent 上下文、采样、评分和候选比较使用同一份任务定义。目录请求只读小型配置，不解析原始 CSV。

## 当前任务范围

两套数据先保留已有的小时级环境预测任务：室内气温、相对湿度和 CO₂ 浓度，预测未来 1、6、24 小时。目标等权、时距等权；相对训练拟合分区选定的基线计算 RMSE skill。基本预测覆盖率为 80%，候选选择覆盖率为 90%。适配器允许分别配置目标、单位、边界、权重、时距和门槛，不要求两个数据集始终使用相同配置。

| 适配器 | 数据语义 | 当前评分范围 |
| --- | --- | --- |
| `agc_cucumber_2018@1` | 黄瓜一级果产量为累计量；供热能耗为 kWh/m²/日 | 环境预测；不将稀疏产量、作物和资源标签混入小时级评分 |
| `agc_tomato_2019@1` | 番茄一级果产量为单次采收量；供热能耗为 MJ/m²/日 | 环境预测；产量、品质保留原始稀疏观测，不插值为小时标签 |

适配器定义“预测什么、如何评测”。每个样本仍由 Agent 分析并提交预测，Agent 继续自主调用工具、选用模型和优化参数。

这些指标是本项目根据原始数据说明定义的预测评测协议，不是对挑战赛经济效益排名公式的复刻。两个数据集具有相同频率和单位的气候观测，因此当前气候预测目标相同；各自的产量、资源、作物和品质字段独立映射，没有把单次采收量当作累计量。番茄根区传感器只覆盖部分时间，产量和品质则为低频记录，暂不作为完整小时网格的必选评分目标。

## 指标与观测可用时间

- 每个目标、每个时距分别报告 MAE、RMSE、Bias（预测减观测的平均值）、归一化 RMSE、基线相对改善、覆盖率和越界数；有量纲的误差保留该目标的单位。主评分按目标权重和等权时距汇总 `(基线 RMSE − 候选 RMSE) / max(基线 RMSE, 候选 RMSE)`，两者同时为零时记零改善。尺度和基线仅在拟合分区估计。
- 五分钟数据按小时均值加载。日汇总在下一日才可见；仅有观测日期的采收、品质和化验记录也延后至下一日。黄瓜按周编号记录的作物统计在该周结束后才可见。这些保守的可用时间是项目的数据处理假设，不是数据发布方提供的精确发布时间。
- 低频记录只在对应可用时点出现，不插值、不向之前的时点传播。番茄总电耗需要峰、谷两项都已知，净用水需要灌溉和排水都已知；缺失项不能按零计算。
- 按原始说明修正黄瓜湿度亏缺设定值单位为 `g_kg`；番茄根区电导率统一标记为原文使用的 `dS_m`。

来源依据为归档内 `ReadMe.pdf` 与 CSV 表头：[2018 黄瓜原始数据](https://doi.org/10.4121/uuid:e4987a7b-04dd-4c89-9b18-883aad30ba9a)、[2019 番茄原始数据](https://doi.org/10.4121/uuid:88d22c60-21b3-4ea8-90db-20249a5be2a7)。定义中的文档摘要用于追踪本次定义的依据。

## 下载与加载

`ecologyrsi-dsh data fetch agc_cucumber_2018 agc_tomato_2019 --data-root <数据目录>` 按目录中的 HTTPS 地址下载、验证归档大小和 MD5，再安全解压；已有完整且校验通过的数据直接复用。服务使用同一目录：设置 `ECOLOGYRSI_DATA_ROOT=<数据目录>` 后启动。网页选择数据集后自动绑定该数据集的目标、指标和评测器，无须手动配置预测模型。

修改定义后重启后端生效。完整定义的摘要参与冻结任务，包括字段映射和可用时间的变动，防止旧运行在数据处理规则变化后继续混用结果。原始数据不进入代码发布包，定义文件随 wheel 和源码包一起分发。

## 执行约束

### 按时间训练与独立评测

新运行使用 `time-forward-calendar/2`：以各优化团队共同的日历时间范围确定 60% 训练、20% 验证、20% 最终测试边界；缺行不会改变团队的分区日期，参考团队不参与确定边界。训练内部再区分模型拟合、不确定性校准和进化训练，保留预测时距对应的隔离窗口。比例是隔离前的时间比例，不等于有效样本比例。

训练调度版本 4 固定每轮的适应、筛选和轮末比较子集，轮内按预测目标时间隔离，轮间显式复用。默认每轮使用 433 个不同预测起点（200 个适应、64 个筛选、169 个轮末比较）；配置 10 轮仍只需要同一批训练数据，计算预算按 10 轮累计。重复训练不能增加独立证据量。单轮配置过大、时间缺口或实际日块不足仍会拒绝启动，不能挪用验证集或测试集补足。

网页“独立评测”使用单独的 `GET/POST /api/ecology-evolution/runs/{run_id}/independent-evaluation`，POST 仅接受 `stage: validation` 或 `stage: final_test`。先完成进化并冻结候选，再执行独立验证；只有验证通过的相同候选可以进入最终测试。各阶段按时间遍历全部合格起点，进行两次逐样本 Agent 推理，工具拟合数据、模型参数、Agent 策略和运行路由必须与冻结产物一致。展示每个目标和时距的误差、偏差、基线改善、覆盖率与汇总结果；不把结果写入训练评分或候选更新流程。

评测数据只能在已打开的阶段令牌内读取。同一事件账本内，原始评测分区只能锁定一个候选，重复点击不会创建新评测；运行中断则封存该分区，重启不会自动重试。推理失败或覆盖不足不能视为通过。协议变化后应创建新运行，旧运行不能混用新的时间切分。

- 数据目录中的适配器 ID、数据集 ID 和领域必须一致；加载时验证目标存在且单位一致。
- `/catalog` 为每个数据集提供 `task_adapter` 和 `evaluation`；网页据此切换预测说明、评测器、样本数量和容量预检。只有登记且就绪的适配器能进入实际训练选择框。
- 创建运行时冻结完整 `dataset_task`、其摘要、目标、时距、适应度配置和数据集专属评测器摘要。客户端不能替换目标或伪造契约。
- 采样器按适配器最大预测时距隔离时间边界；执行器据此生成预测网格，评分和配对证据按相同目标权重计算。局部优化的目标集合也来自冻结配置。
- 候选比较验证任务契约及其配对证据，按适配器的实际增益门槛判断。恢复运行时若适配器已经改变，则拒绝继续混用两套任务定义；开始新运行使用当前定义。

## 扩展方法与验证

接入同类数据时，先确认字段、单位、采样频率和标签的时间含义，再添加定义文件并在来源目录设置 `adapter_definition`。通用 CSV 加载器按定义中的表清单执行，不再为黄瓜和番茄维护两套加载分支。已有小时级评测支持不同目标组合与时距；新增日级产量、事件级采收或品质任务，需要实现对应的数据对齐、基线和评测器；定义校验会拒绝将低频字段直接用作小时级标签。未实现的主评分或诊断指标也会被明确拒绝。

回归测试覆盖独立契约与摘要、跨数据集和单位不匹配、篡改任务、不同目标权重与时距的真实评分路径、目标成熟时间隔离，以及候选比较门槛。使用“两目标 × 两时距”的测试任务检查通用执行路径没有依赖固定九项网格；网页测试验证黄瓜与番茄的实际切换和容量预检。
