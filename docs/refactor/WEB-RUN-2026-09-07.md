## 真实运行发现的问题与修复

第一份研究方案引用了冻结知识快照以外的依据，宿主按原规则拒绝并请求修正。这是证据边界在正常工作。

第二份方案已满足宿主研究合同，但 DSH 在写入前的工具顺序校验失败，并归类为 `structured_result_persist_failed`。实际不是 SQLite 故障：模型先把 `web_search.queries` 写成字符串，收到参数错误后，以相同 retrieval_key 改成数组并成功检索；旧校验要求每一次检索调用均成功，因而仍拒绝了已经修正的整个会话。

本轮对 `integrations/dsh_ecology_plugin/lib/runtime/stage-runner.js` 做最小修正：只允许明确可归因的参数校验错误，且要求相同 retrieval_key 的后续合法调用成功。错误结果必须绑定原 callId、turn、step、sourceEventSeqs，并与本地参数校验错误文本相符。两次调用都消耗原有最多三次检索预算。授权错误、缺失结果、未修正错误、错误来源、顺序违规和失败修正仍然拒绝；Skill 必须先成功，终止工具要求不变，宿主冻结证据校验不变。
