# 0.3.60 数据加载优化

本次调整网页读取架构，覆盖首屏、历史、过程、候选、训练数据和训练轨迹。原有研究闭环与追加式实验账本保留，已完成实验不重新执行。

## 原因与调整

实测旧页面选择一次运行会读取约 2.1 MB 完整运行详情，其中约 1.43 MB 是尚未展开的训练轨迹；隐藏区域也会参加整体重渲染。历史运行、事件、训练样本与运行选择相互等待，进一步拖慢可用时间。

现在分成三层读取：

1. **先读概况**：首屏只取目录、最近 5 条运行摘要和选中运行概况。更早运行通过“加载更早运行”分页读取。
2. **打开区域再读详情**：过程、候选、训练资产和人工审核各自读取；区域失败可独立重试，其他页面仍可使用。过程首次只读取最近 60 条事件，样本保持分页。
3. **展开后读取完整轨迹**：训练资产先显示轻量列表，点击“加载完整训练轨迹与复现证据”只读取对应候选的完整证据。训练数据每页 20 行，只在数据工作区读取。

浏览器合并相同 GET 请求；目录缓存 60 秒，数据描述及样本页缓存 15 秒，最多 16 条。手动刷新清除短期缓存。完整训练轨迹最多保留 4 条。已加载区域按运行修订复用，重复切换不重新下载同一修订详情；活跃运行的常规详情刷新间隔为 15 秒，切换区域、手动刷新或结构变化会立即读取；进度监控独立更新。

已完成运行的已校验概况另存为持久化读取快照，正常重启时直接展示概况。快照包含代码版本、投影器身份、账本修订与正文校验和；不匹配或损坏时回到完整校验重建。历史列表与概况使用不同缓存文件，避免互相覆盖。活动运行继续读取当前状态，归档、调度与实时并发信息在响应时重新获取。

服务端按“运行、修订、区域、候选”缓存独立详情，相同读取合并构建，限制为 64 条／16 MiB。状态、实时进度与调度信息仍在读取时生成。事件尾页复用已校验的运行事件，避免再次从 SQLite 解码全部历史。

## 一致性

- 迟到的详情响应不能覆盖更高修订的运行状态、进度或用量；旧区域快照有明确提示。
- 切换运行后丢弃旧运行的异步结果；缓存与宿主上下文和运行身份绑定。
- 已完成实验的吞吐率按完成时刻计算，避免随着以后查看时间推移而持续下降。
- 训练摘要与完整详情使用同一个训练样本身份；分页保留冻结的数据、分区与协议摘要核验。
- 修复初筛已淘汰候选的封存样本被误报为“缺少科学评测”的问题。仅接受对应候选、代次、初筛阶段、冻结 cohort 和记录数一致的筛选证据。
