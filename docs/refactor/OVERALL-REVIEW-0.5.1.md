# 0.5.1：整体代码审查与优化

## 结论

当前主链可以继续沿用：追加事件账本保存事实，状态机管理运行与候选，候选编译生成受约束的执行方案，统一评测合同与晋级门槛决定是否保留改进。本次没有发现需要再次整体替换框架的依据；确认并修复的问题主要集中在创建合同、候选状态投影和页面读取边界。

审查覆盖创建、研究选择预测器、候选编译与评测、事件回放、分区接口、前端状态合并和交付清单。修复沿用现有主链，删除错误的数据合并和无用的详情构建，没有增加平行调度器或新的缓存框架。

## 已修复的问题

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 完整任务清单与简化创建请求读取绑定的位置不同 | 原生协议只在清单内声明时，初始化分支可能错误；顶层预测选择字段可能被忽略 | 创建、预检、任务解析共用绑定解析；合并五项执行/预测绑定，冲突在创建前拒绝 |
| 未编译候选展示运行初始预测器 | 模型已经选择另一方案，页面仍显示基线方案 | 从该候选的持久化基因组读取预测器和残差启用状态；有评测证据时继续使用实际评测记录 |
| 过程接口先构建完整详情再删除字段 | 虽然响应较小，服务端仍承担算法详情、推理轨迹、完整基因组、研究计划和指标的构建成本 | 在共享投影函数中直接构建摘要，详情页才构建重字段 |
| 过程摘要、候选详情和协作选项合并进同一个候选数组 | 异步响应可能混合不同修订的分数、状态与证据 | 三类集合独立保存；过程卡片和过程样本选择使用过程摘要，保留原有工作区版本及过期提示 |
| 人工审核选项依赖先访问候选页 | 直接进入审核页时，可选候选可能为空 | 协作接口直接返回满足原有资格条件的最小选项，保持资格规则不变 |

真实 Chrome 使用当前前端源码和 0.5.1 独立后端，数据为已完成历史运行的 SQLite 快照。验证首屏、过程摘要、候选与样本分页、训练数据分页、单项轨迹展开、同修订缓存复用、局部失败重试、历史分页以及真实创建表单合同。创建请求被拦截，不会在生产账本发起实验。隔离后端关闭自动恢复，避免重复执行运行。

本次评审期间，生产服务中已有一轮新的自进化 `run:a39ff5dc-af48-43ad-8c9d-5484d050a9d2` 正在执行。因此未重启生产后端或替换其 DSH 运行实例。源码和安装包为 0.5.1；已有进程仍按其启动时的 0.5.0 执行，待该轮结束后再切换。不能将页面静态文件版本当作运行实例已经升级的证据。

## 交付验证结果

- Python 全量 1,485 项通过，包含真实温室数据评测；DSH 与前端 JavaScript 223 项通过，页面 smoke 通过。
- 真实 Chrome 11 项验收通过，无未预期页面错误；核验实际加载的前端资源与本地源码一致。
- 同一个四候选历史运行、内存状态预热、交替执行 12 次的测量中，候选摘要构建中位数从 27.72 ms 降到 9.85 ms，减少约 64.5%；新旧摘要内容相同。这仅衡量该段投影构建，不是整页或冷启动耗时。
- 交付目录为 `dist/0.5.1/`，包含 wheel、源码包、DSH 插件及完整交付压缩包；构建与安装验证日志保存在审计目录，包校验值保存在交付目录 `SHA256SUMS`。
- 生产中正在运行的 0.5.0 实例未被本次验收重启；0.5.1 的页面与接口联合验收通过隔离后端完成。

## 仍应关注的架构问题

1. HTTP handler、投影和策略模块仍偏大，分别约 4,200、6,100、4,900 行。后续应围绕创建、运行控制、候选读取和研究编排等明确职责逐步拆分，同时保持单一合同与测试入口。本次先修复职责交界处的实际错误，没有为减少行数进行大范围搬运。
2. 页面按区加载已经建立，但活动运行的状态回放、过程轮次和执行证据仍随历史增长。下一步应基于真实耗时采样确定热点，再决定是否增加事件索引或更细的摘要；不应继续无依据地叠加缓存。
3. 工程稳定性与科学收益必须分开判断。注册预测器选择、参数优化和晋级规则通过测试，不代表已获得更好的独立预测效果；应待真实运行完成，依据冻结评测合同和完整执行资格分析结果。

本版适用于现有单机本地研究部署；本次未开展跨进程水平扩展或长时间高并发压力验证。
