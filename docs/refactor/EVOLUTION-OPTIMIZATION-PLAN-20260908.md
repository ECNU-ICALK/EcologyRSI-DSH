**4. 第一优先级：建立修改可执行性检查。** 当前已有 genome 与行为摘要，但“摘要不同”只是版本身份不同，不能证明运行行为有变化。

每种允许修改的字段必须有一条可检查的映射：修改字段 → 实际消费者 → 编译/提示/工具输入变化 → 可能影响的预测单元、区间或执行成本。目录中没有生产消费者的能力，不向新运行的变异器暴露。身份、时间戳或 lineage 改变不属于有效行为差异。

每项修改提议要说明具体训练证据、目标弱项、受影响单元、可能退步单元和验证方式。默认一次解决一个明确问题；最多两项仍可保留，但不能把多个无关改动捆绑后无法归因。允许 keep，修改次数不作为奖励。

可执行性预检只判断“是否有真实影响路径”，不要求在同一已看标签批次上证明改进，也不能把预检数据伪装为后续独立检验。对提示策略变化检查实际渲染提示和可调用能力的变化；对数值参数检查工具消费者；对拟合策略检查实际工件变化。低成本固定输入探针仅用于行为诊断，记录其训练数据暴露。

对当前候选 4，下一版应拒绝将未接通的 UQ-only 修改送入点预测比较，原因明确为“能力未接入或与优化目标不匹配”。以后若保留 UQ，必须接通冻结 Agent 最终预测的校准与区间输出，增加覆盖率、宽度和区间评分；不能只用底层 ridge 的残差宣称 Agent 融合预测已校准。若 UQ 还要影响点预测选型，则需显式实现该决策路径并独立验证。

**5. 第二优先级：分离来源完整性、执行可靠性与预测质量。** 当前 `strict_agent_chain_pass` 要求所有 attempted 样本完成 Agent 链。它与候选覆盖门槛叠加后，实际形成更严的全成功条件；局部和轮末晋升都受影响。同时，paired 路径仍可能在故障混合的批次上提出科学参数修改。

新版应明确三个判断：

- 来源完整性：每一个发布为成功的预测，必须有完整、真实的 Agent 与工具证据，要求 100%。禁止 Host 静默替代、伪造工具收据或把失败填成成功预测。
- 执行可靠性：每个计划时点必须有成功或明确失败终态；按冻结规则统计成功率、失败分类及恢复成本。基础设施错误不会变成农业参数错误。
- 预测质量：在符合预声明配对、覆盖、时间块和缺失处理规则的数据上比较。服务故障不能通过让一方多扣分而产生“科学改进”。

完整、可靠的配对数据是首选。传输与服务故障只能在评分和揭示反馈前，按预声明规则有限恢复；冠军和挑战者采用对等预算、相同样本与上下文。若严重故障、两臂故障不平衡或有效时间块不足，则标为证据不足，保留旧版，不能只挑共同成功且有利的子集晋升。残余缺失如何处理和覆盖阈值是多少，必须作为新版任务契约提前冻结，并同时报告对部署有效性的影响。

| 观测状态 | 允许动作 | 科学状态 |
|---|---|---|
| 短暂传输故障，尚无已接受结果 | 同身份、有界重放；计入恢复预算 | 未形成该时点证据 |
| 输出耗尽或协议格式失败 | 保留诊断；有预算时采用预定义紧凑恢复，不原样扩大重试 | 执行失败，不推导预测参数优劣 |
| 结果已接受，响应或遥测晚到 | 查询或重交同一不可变结果，补用量对账 | 保留既有成功，不重跑模型 |
| 越界预测或可纠正内容问题 | 在固定预算内由 Agent 修正；保留原始尝试 | 如实计入约束与修复记录 |
| 身份、工具权限、未来信息边界错误 | 停止对应执行范围并修复 | 证据无效，不进入选优 |
| 批次运行可靠、预测退步 | 对训练误差反思，提出可执行小改动 | 可进入待验证 |
| 批次被运行故障主导 | 优先执行恢复或有限诊断 | 不用混合失败分数驱动科学修改 |

采用这一设计不是降低来源要求，也不是删除失败惩罚，而是使系统能够分清“没有可靠结果”和“有可靠结果但预测较差”。

**6. 统一局部比较与轮末选择。** 当前局部九个 cell 的非退化容差近似 0（1e-12），轮末最差 cell 的容差却为 -0.01。逐样本 Agent 具有随机性，即使仅修改 CO₂ 1h，也可能在其他单元出现随机波动。这些规则需要由同一冻结决策契约提供。

契约统一包含：评分公式及方向、目标权重、实际增益阈值、各目标/时效的非劣容差、可靠性条件、时间块要求、重复推理安排、缺失处理、成本约束和提前停止规则。物理边界与数据隔离仍是硬约束；预测误差容差根据量纲、训练数据波动和任务实际意义确定，不能为使本次候选晋升而事后放宽。

当前 0.005 的实际增益阈值可作为首版参照，不应无证据立刻替换。1e-12 只适合数值一致性检查，不应未经解释就代表全部预测任务的实际非劣要求。局部比较和轮末比较可有不同证据强度，但差别必须明确、来自同一契约。

局部决策采用四种清晰结果：待验证、接受、保留原版、证据不足。证据不足时只允许预先规定的有限额外时间块与预算；不反复看同一数据直到显著。进入下一次反思时，父版本仍是已接受版本；尚未验证的新版本不能默认为下一次变异的正确基础。

初始冠军登记不算新旧比较胜利，局部接受不等于轮末胜出，训练选优也不等于独立验证。界面和内部命名均应统一这些边界。

**7. 让 Agent 策略成为真正可继承的对象。** 用户要求的自主模型选择继续保留。新版扩展已有 Agent policy，不新增平行记忆系统。

| 策略内容 | 要记录和继承的内容 |
|---|---|
| 模型与工具选择 | 在何种可见条件下考虑哪类工具；默认参数；允许的自主调整范围 |
| 分析停止 | 何时证据已足够、何时追加工具或评审；工具预算是上限而非目标 |
| 最终预测 | 直接预测、模型输出、融合或修正；证据引用；融合权重/可复算方式 |
| 目标影响域 | 哪些目标×时效是本次重点、哪些需要保护；记录意外跨单元变化 |
| 训练经验 | 有来源的误差聚合、工具表现、有效/无效修改和适用条件；容量有界 |
| 版本身份 | 提示内容、策略参数、工具实现、拟合工件、模型路由和数据契约 |

不需要每个时点都重新探索全部模型。外层反思负责积累通用决策经验，内层 Agent 用当前观测判断适用性并保留例外处理能力。复杂样本仍可深入分析，不能为了降本把系统改回固定模型直接输出。

候选多样性应覆盖实际策略差异，例如稳健保守、特定时效修复、不同特征模型、不同工具选择/融合方式。由研究 Agent 根据弱项选择方向，不要求用户在启动页配置预测器。行为等价的候选不重复投入整轮预算；去重依据实际执行策略而非仅比较参数字符串。

**8. 缩短单时点执行链路。** 当前已共享 origin context、限制工具上限、按需触发 critic；优化应进一步减少模型循环中的重复内容。

将冻结的数据与任务说明作为稳定上下文，动态部分只保留当前需要的历史窗口、变化摘要、缺失情况及候选策略。摘要必须包含足够信息或能按需解析，不能只给 Agent 一个无法读取的 digest。详细原始轨迹保留在审计中，避免每次对话重复搬运。最终输出保留数值、方法、证据和必要短原因，长篇通用说明放到批次反思。

简单样本以 0–2 次数值工具调用作为待验证的预算起点；不确定样本可在现有上限内升级分析。先验证紧凑上下文与输出协议，再调整 8192 等输出限制，避免单纯减小上限加剧截断。继续使用 GLM/Flash 进行同条件试验；未来更换角色模型另立冻结实验，不在运行中静默切换。

在现有缓存上补齐规范化预测请求身份：拟合版本、规范模型 ID、补齐后的参数、因果输入、目标、时效、预处理与工具版本。不同 `call_id` 或候选别名若指向完全相同的确定性计算，可以复用结果，但仍须为当前 Agent 发放可验证的证据收据。不能跨可用信息边界复用，不能把同一缓存结果算作新的独立推理副本；失败也不能永久缓存。

数值工具先按证据优化，不把当前毫秒级耗时当成主瓶颈。模型拟合与单点预测保持分离，已有磁盘拟合缓存继续复用。

**9. 收敛调度、恢复和预算。** Host 管理逻辑工作窗口、内存与运行生命周期；DSH 管理真实账户配额和模型路由公平性。保持两个边界，但不让两层各自独立猜测同一提供方容量。

用户配置的 64 作为上限。实际初始准入依据短诊断或近期可靠容量，逐步探测；保留已有 AIMD。GLM 与 Flash 目前归到 `pjlab`，后续应在账户共享总配额下区分模型和角色队列，给评审与反思保留公平机会，不能简单拆成两池绕开共享配额。

已有全阶段绝对 deadline 应保留，并记录排队、模型执行、工具、提交与结算各段耗时，在总期限内为最终提交留余量。跨 DSH、样本适配和运行恢复的次数应归入同一个逻辑时点恢复账本，防止层层都“有限重试”但总量失控。

预算必须分清：

- 可强制的执行上限：真实模型请求/子任务数、工具次数、修复次数、在途数、单次输出上限、阶段期限。
- 原生 token 工作预算：只有能在每次真实模型调用前预留输入与输出上界并共用恢复预算时，才可称硬准入；目前原生执行没有这一完整原子能力。
- 已发生用量：提供方会话遥测是延迟的累计值。展示未缓存输入、缓存输入、输出、完整度和在途未结算部分。软阈值触发的是“停止新增工作，继续结算在途”，不能宣称精确账单封顶。

预算耗尽是明确结束或暂停原因，不能靠无限恢复耗尽资源。已接受结果是唯一成功终态，用量晚到不应使其回退为预测失败。暂停/取消停止新增请求；恢复重新绑定已接受结果，避免重复评分或重复产生模型调用。

**10. 调整探索预算和无提升处理。** 当前每轮计划最多 1970 次时点执行：256 次初筛、700 次局部配对、1014 次轮末比较。5 轮共 9850 次、88650 个评分单元，尚未包含重试和独立评测。控制器应在启动前清楚显示实际工作量。

第一阶段保持现有正式样本量，先修正确性与单样本成本，避免同时改变所有条件。第二阶段再引入预声明的渐进分配：少量时间块诊断明显故障或劣化，再为有希望的候选投入完整比较。小样本只用于诊断和有界淘汰，不能绕过正式采纳的时间块与非劣要求。

| 候选/轮次结果 | 下一步 |
|---|---|
| 有可靠合格候选 | 按冻结规则选择 Top-2 继续 |
| 全部因运行故障无法比较 | 执行修复或有界恢复；不直接产生新的农业假设 |
| 运行可靠但全部预测不佳 | 保留 incumbent；给有限修复探索预算，再重新规划 |
| 修改没有可执行影响或行为重复 | 拒绝/合并，跳过无意义对照 |
| 后续配对有实际改善 | 接受局部新版本，继续下一批 |
| 无改善或证据不足 | 保留旧版；有预算时按既定规则补充证据 |
| 连续轮次无可靠进展 | 调整研究方向或按停滞规则结束，不强制选出新赢家 |

轮末只让完成必要证据且有资格的版本进入比较。没有合格挑战者可以直接保留 incumbent，并记录哪些工作被规则性跳过。之后若采用按差距与随机性分配推理副本，必须在新运行前冻结规则；不能看了分数以后临时增加有利候选的次数。首版不建议同时重写评分和削减副本。

**11. 数据适配、时间证据与独立评测。** 两个 dataset adaptor 继续分别定义字段、单位、可用时间和目标。近期以黄瓜完成闭环，以番茄验证适配与另一段数据上的可运行性。当前两者均先做气候预测；产量、品质、资源效率需要独立任务和相应时间尺度，不能填入小时网格凑样本。

保持按共同日历边界划分的训练、验证、测试与隔离窗口。拟合、预处理、尺度、基线只使用允许的训练部分；区间校准若接入则使用指定校准部分。采收、日汇总、控制计划等均以真实或保守定义的可用时间进入上下文。

本次 433 是训练内去重预测时点数，不是 433 个统计独立观察。当前 50 点批次只有 3 个 24h 时间块；5 轮复用和两次模型推理副本都不会新增独立时间证据。统计报告同时给出时点数、时间块数、跨度、重复使用次数和推理副本数。

训练内比较继续承担探索选优。可设置预先冻结、按时间块组织的稳定性检查；一旦用于反思就属于训练证据。不要为了方便停止条件再建立一个反复偷看的“准测试集”。多次自适应比较的统计区间须标为探索证据，最终泛化结论来自后续冻结评测。

独立评测沿用现有独立服务与暴露令牌：进化结束后冻结同一候选的 Agent 策略、经验、路由、工具契约、拟合规则和已有工件，先验证，再对相同通过验证的版本进行最终测试。评测期不改候选或策略版本，不利用评测标签反思、重新拟合或校准；单样本 Agent 仍按冻结策略和起点可见信息，自主选择登记工具与允许的参数。需要计算其他允许配置时也只能使用原有训练拟合数据与冻结规则，不能更新共享策略。若验证结果指导了后续开发，则此分区已经成为开发证据，不能再把重测结果称为首次独立验证。

真实留出数据不用于调试新协议或测试故障恢复；使用训练诊断集或合成故障。独立阶段发生中断时保留现有封存语义，任何更灵活的恢复均须另行设计同候选、同计划、同证据的恢复契约。工程稳定前不消耗最终留出资格。

首屏突出运行阶段、已结算工作量、成功率、有效吞吐、已观测用量与完整度，以及已验证改进状态。技术队列、工具产出、结构化提交和宿主结算进入展开的执行漏斗。ETA 说明基于近期吞吐和最大计划工作量，不作为完成时间承诺。

结果分三个层级：正式保留版本；正在进行的新旧版本比较；批次诊断。当前正式分数为空时，明确显示仍保留种子、尚无轮末结论，不用最新 batch 分数补上。现有“新方案已生成，尚未比较效果”文案保留。

**14. 验收设计与可交付标准。** 工程可用与预测有效分别验收。系统正确地判断没有改善、保留旧版，也是合法结果；它不等于已交付一个更好的预测模型。

以下数值为建议的工程目标，不是已经实现的收益。采用同一冻结训练诊断清单、同样模型路由与资源上限进行新旧链路对照；成本包含全部失败、恢复和评审，并除以有效终态时点。预先确定测试样本数与规则，小规模 8–16 点仅作烟测，正式可靠性测量至少使用 100 个时点执行并报告样本量与区间。

| 维度 | 建议验收标准 |
|---|---|
| 执行可靠性 | 诊断集有效时点成功率目标 ≥98%；不丢失已接受结果；完整披露失败与恢复 |
| 成本与时延 | 每有效时点总 token 较同条件基线降低 ≥50%；planner 中位耗时降低 ≥40%；同时报告 P90/P95，不能以牺牲预测质量换速度 |
| 来源与隔离 | 100% 成功预测有完整 Agent 来源；没有 Host 静默替代、未来标签暴露或评测反馈回灌 |
| 修改有效性 | 未接入能力、行为无变化及影响域不匹配的提议不进入正式配对；每项采纳有实际版本差异及后续证据 |
| 决策正确性 | 生成、待验证、局部接受、轮末继承、独立验证分别可追溯；initial_champion/applied 不增加“已验证改善”计数 |
| 比较公平性 | 相同冻结时点、信息边界、评分与恢复预算；基础设施污染严重时判证据不足；不按有利子集晋升 |
| 恢复与控制 | 断网、响应丢失、遥测晚到和服务重启不导致重复评分；暂停后无新增模型请求，在途任务有可查终态 |
| 页面数据 | 同快照所有页面给出一致进度、候选结果与用量；只有 token 更新时不重新读取候选工件 |
| 页面性能 | 建议本机首屏可交互目标 ≤2 秒、monitor P95 ≤500ms；在 1千/1万/10万事件回放负载下测量，首屏不加载全量历史 |
| 端到端 | 先完整 batch 新旧比较，再完整一轮，最后 5 轮；至少能明确执行一次接受或保留决策，不强制制造赢家 |
| 科学交付 | 冻结版本通过所需未来验证与最终测试才称预测有效；未通过则如实交付评测结论，不用训练分数代替 |

来源要求 100%、工程成功率目标 98% 和正式候选覆盖门槛属于不同指标；98% 本身既不证明晋升合格，也不能替代冻结决策契约。各目标必须在前置诊断后冻结，不能运行不达标就悄悄改验收线。

后续交付应包含：可执行版本与启动方式、冻结运行清单、数据/adaptor 说明、默认预算及边界、关键阶段证据、性能与失败统计、独立评测报告、已知限制。若本次任务没有可靠改善，应明确保留版本及原因。

**15. 实施时应避免的方向。** 不以增加 epoch、增加并发或提高 token 上限作为主方案；不为降本取消逐样本 Agent；不强制固定一个预测器；不把成功子集的好分数当正式胜出；不把多个数据集、产量任务或更复杂模型同时加入本轮改造；不另建一套日志状态、记忆或工作流系统。先让一个可执行修改在公平比较中得出可信结论，再扩大规模。
