**自进化优化：第一阶段实施与验收记录**

本轮按已确认方案，先修复进化判断，再降低重复执行与页面读取成本。代码已写入现有项目，保留逐时点 Agent 自主预测、批间修改、后续配对检验、轮末选择与独立评测的主流程。本文是本轮源码变更记录，整份优化路线图尚未完成，也尚未发布新的正式版本。

**已经落地的变化**

| 范围 | 当前行为 | 主要实现 |
|---|---|---|
| 修改可执行性 | 不再向局部编辑器提供未接入的 UQ 及没有替代实现的 feature/fit 切换；底层变异入口也拒绝 UQ 切换 | `evolution/genome.py`、`application/formal_trajectory.py` |
| 修改依据 | mutate 必须引用训练证据并声明影响单元；目标/时效残差系数不能宣称直接改善其他时效；无效提议保留父版本 | `evolution/local_edits.py` |
| 故障与反思 | 配对批次只要仍有失败时点，就记录 keep 和原因，不调用科学编辑器；恢复时遇到已有修改提议也会复核该限制 | `application/formal_trajectory.py` |
| 来源与可靠性 | 单独记录成功预测来源覆盖率、成功来源是否完整、执行是否全部完成；科学来源检查使用成功预测收据，失败时点仍如实失败 | `core/agent_prediction.py`、`evaluators/sample_execution.py`、`evaluators/registry.py` |
| 选择契约 | 新运行的局部/轮末比较共用冻结评分配置中的实际增益与单元退步容差；配置与局部比较摘要绑定，回放复算同一规则 | `evaluators/fitness.py`、`core/search_policy.py`、`evolution/champion_challenger.py` |
| 执行覆盖 | 轮末按成功时点数/计划时点数判覆盖，目标权重齐全不能掩盖预测缺失 | `evaluators/generation_comparison.py` |
| 重复工具计算 | 同一不可变 wave 内，相同工具、版本和补齐默认值后的参数复用成功计算；不同调用 ID 仍各自持久化收据，并受调用总数上限约束 | `integrations/prediction_binding.py` |
| 执行准入 | 配置的 64 保持为上限，初始准入最多 8；成功后逐步增加，拥塞时沿用现有退让机制 | `execution/sample_admission.py` |
| Agent 分析停止 | 动态预测契约提示普通时点先考虑 0–2 次工具调用，必要时升级；继续允许直接预测、选择工具、融合和修正，硬上限仍为 6 | `evaluators/dsh_sample_adapter.py` |
| 候选读取 | 候选列表读取摘要；选择后通过独立 candidate 视图读取对应指标与产物；浏览器最多保留 4 份详情，处理并发读取、错身份和切换竞争 | `api/workspaces.py`、`api/catalog.py`、浏览器 `catalog.js` / `render_candidates.js` |
| 缓存失效 | monitor 返回工作区 revision；只有 Token 计量回执变化时，不重新构建/请求候选与训练工件 | `api/projection.py`、浏览器 `catalog.js` |
| 上下文与静态资源 | 当前压力只来自有活跃计量的会话，终态不能被迟到回执重新标成活跃；历史会话最后读数的最大值另存。补齐训练轨迹脚本的静态白名单，修复直接访问返回 404 | `core/dsh_usage.py`、`api/projection.py`、`api/shared.py` |

新评分配置采用实际增益阈值 0.005、单元退步容差 0.01、轮末覆盖下限 0.95。后两项收敛到既有轮末标准，不依据这次候选得分临时调参。局部三日块与轮末更强的时间块要求继续保留。

成功来源合格不等于可以晋升。当前正式配对仍单独要求两臂的完整时点、目标网格和时间块证据；残余缺失会产生 `paired_scoring_evidence_incomplete` 并保留原版，不选择有利的共同成功子集。`strict_agent_chain_pass` 的旧全链完整性度量仍用于审计；新的 `successful_agent_provenance_pass` 与 `execution_complete` 分别解释来源与可用性。

本轮工具缓存仅在同一 wave 内复用同一工具的等价参数请求，不跨候选、预测起点、训练拟合边界或独立推理副本复用，也未声称已经完成不同模型别名间的等价识别。当前工作区 revision 保守地只排除 Token 计量事件，其他事件仍触发内容刷新。

**运行与后续边界**

本轮没有重启既有前后端、安装替换其插件、恢复旧实验或开启独立留出评测。只读检查时，原 `run:46aa2f0b-3442-420c-9743-2474762b5b86` 已处于 paused，最后状态更新时间为北京时间 2026-09-08 22:07:13；本轮未改变其状态。隔离浏览器测试服务已在验证后关闭。

新代码需用新建运行验收，不把它热混入旧实验。下一阶段按原计划继续：

1. 在冻结训练诊断清单上，以 GLM/Flash 进行真实执行对照，统计全部失败、恢复、有效时点耗时和用量；验证紧凑停止提示与冷启动配置，达到标准后再增加运行规模。
2. 完成账户总配额下的模型/角色公平调度、跨层恢复总预算、已接受结果与迟到遥测的故障注入验收。本轮没有重写 DSH 的这些机制。
3. 基于可靠执行证据实现全失败、无改善与停滞处理，再考虑渐进样本量和副本分配；扩展已有策略继承，避免引入第二套经验系统。
4. 做真实大账本加载与完整 5 轮验收，之后才启动冻结策略的独立验证/最终测试。成功率 ≥98%、每有效时点用量降低 ≥50%、planner 中位耗时降低 ≥40% 仍是待测目标，本轮不宣称已经达到，也不宣称预测能力已经稳定提升。

**后续：小批量实验默认参数**

按追加要求，新建运行默认 5 个 epoch，每个入围方案每轮 100 个预测起点，每批 10 个，轮末比较 50 个；候选预算随 5 × 4 自动为 20。初筛维持 4 × 64，轮末三臂各做两次独立推理，所以每轮最多 936 次完整预测，5 轮最多 4,680 次，不含重试。50 指训练区的轮末评测，独立验证与最终测试继续单独启动。

小训练 batch 使用跨至少 24 小时的固定数量起点，做探索性配对增益与单元不退化比较，仍要求两臂完整的 Agent 预测证据；不要求这 10 个样本完成局部三日块统计确认。轮末 50 个起点只按时间分散抽取，覆盖至少 8 个日块，继续执行原有跨日稳定性与至少 40 个有效样本要求。前端、创建时容量校验、冻结样本阈值及恢复时校验一致；不是把相邻 50 小时直接当成 8 日证据。批次之间继续按所有目标成熟时间隔离，数据标签不参与选样。

- 真实 2018 黄瓜（AiCU）和 2019 番茄（AICU）的新默认容量校验通过，两者轮末均为 50 个起点 / 8 个日块。
- 相关核心回归 42 项通过；调度、评分和 HTTP 回归 67 项通过；插件 smoke、独立评测 UI 与工作区读取检查通过。

**后续：参数约束与执行逻辑一致性**

进一步复核后，将新建训练运行的默认值与边界收敛到 `evolution/parameters.py`。后端目录发布参数规则；网页优先读取当前数据集适配器绑定的评测器规则，使用同一规则设置表单、校验请求和计算就绪状态。离线初始规则有契约一致性测试。创建与真实模型预检共同校验，显式传入的每轮候选数不会被悄悄改回 4。预测向量宽度来自数据集，不固定为 9。

| 约束 | 新运行规则 | 理由 |
|---|---|---|
| epoch | 默认 5，整数 1–50 | 明确执行预算，不通过取整改变用户输入 |
| 每轮候选 | 固定 4，入围 2 | 与当前 Top-2 主流程一致 |
| 总候选预算 | 4–256，且至少为 epoch × 4 | 覆盖全部轮次，容量预览与创建均验证轮数范围 |
| 优化样本与 batch | 默认 100 / 10，batch 至少 2，总量必须整除 batch | 当前轨迹使用等长配对批次，批间按目标成熟时间隔离 |
| 轮末样本 | 默认 50，下限来自当前评测配置（两套数据均为 40） | 起点数量与时间覆盖分别校验，取消连续小时采样下的 169 硬下限 |
| 时间证据 | 默认至少 8 个日块，至少 4 个连续 3 日窗口 | 日块数足够但日期不连续时，创建前拒绝 |
| 局部更新 | 新训练运行统一采用探索性完整配对比较，并在任务中冻结策略 | 不再在 batch 48→49 时突然切换判断方法；epoch 承担统一确认 |
| 重复推理 | 两个独立副本都检查完成后，才决定下一轮父版本 | 修复第二次推理失败后仍沿用旧可选标记的问题 |

保留完整预测来源、无缺失配对、实际增益、各目标不退化以及数据隔离要求。小样本与重复 epoch 的结果仍是训练选择证据，不能宣称独立泛化改善。参数规则的改变对新建运行生效，既有实验不通过重写账本改变其配置。
