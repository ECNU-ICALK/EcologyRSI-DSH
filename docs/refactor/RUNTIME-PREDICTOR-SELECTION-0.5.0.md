# 0.5.0：运行中自主选择预测方案

## 交付行为

新建温室自主运行不再要求用户配置预测器或评测器。用户选择数据、策略模型、独立评审模型和预算；研究模型根据每轮的资料、当前方案和反馈，决定是否启用残差模型、采用哪一种已登记方案，以及下一步如何优化参数。

运行以仅用训练段选定基线作为比较参照。研究阶段可以选择统一残差、分目标残差、分目标/时距残差，或在基线对齐方案上按时距启用残差。切换方案使用登记默认参数，后续修改使用实际候选模型的参数边界。模型也可以切回基线对齐方案的零残差默认值。只有通过现有配对比较、执行资格和评审条件的候选才会被保留。

## 架构与约束

- 创建请求使用 `prediction_selection_policy: model_during_run@1`，不发送预测器、评测器和种子模板；服务端拒绝该策略与预选字段同时出现。
- 服务端冻结四种可用预测器及 `greenhouse_multihorizon_time_forward@4`。这项合同使用现有统一评测实现，固定三项目标、1/6/24 小时时距、数据边界、评分基线与晋级条件。
- 研究综合、候选提案及代际反思获得预测选择语义和目录；沿用已有的 `select_registered_pipeline`、有界参数变异和候选编译流程，没有新增平行执行框架。
- 零残差的基线对齐任务跳过残差拟合，明确记录 `baseline_only`，不计入求解失败；按时距启用时，仅拟合该时距的三项目标。
- 页面显示实际候选的预测器和基线使用状态。创建入口不再读取预测器选择；人工审核移除依赖创建下拉框的参数提示。

当前可优化范围是四种已登记方案的选择与参数，尚不支持模型生成并执行任意新预测器代码。本次工程验证不代表已经取得新的预测收益。
