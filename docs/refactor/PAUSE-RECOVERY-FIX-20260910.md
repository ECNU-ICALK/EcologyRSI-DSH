# 启动中止与自动恢复修复 · 2026-09-10

## 原因与真实证据

本次检查主网页 8848 和三个本地服务账本，确认用户看到的“刚启动就暂停”包含不同问题：

1. `c72bab22…` 在 9 月 9 日 19:26 被上次工程验证主动暂停。新建失败后网页回到这条旧记录，让人误以为新运行自动暂停。
2. `872bf35b…` 曾因 DSH 暂时不可用，在 6 次 Host 重试后进入人工恢复状态。
3. 9 月 10 日多次新建未通过四角色模型预检，没有产生新的 `RunCreated`。DSK Flash 有时把 Skill 或 structured_output 调用写成普通 DSML 文本；旧分类器又漏掉“先有真实工具调用、最后才输出 DSML”的情况。
4. 21:13 创建的 `010f70a6…` 已通过预检，但在首批完成 4 个起点后，于 21:18 因 GLM 单次输出达到 8,192 tokens 而失败。仅修复网页与预检重试还不足以解决实跑中断。
5. 自定义模型路由未声明实际 API 约定，适配器依赖通用 OpenAI 默认值。DSH 的 `AgentOptions` 只读取 provider/model/maxTokens，不能靠向该对象添加 reasoningEffort 来控制推理。实际子会话的 request/header 证实了这一点。

直接接口对照测试使用无业务数据的工具预检输入，记录工具名、结束类型、用量和时长，不保存或展示隐藏思维链：普通请求可以返回真实工具调用；附带 strict:false 的请求曾返回 DSML 文本，但重复实验发现去掉 strict 后仍有间歇性 DSML。因此，不能将 strict 字段认定为唯一根因，也不能保证仅修改参数就消除远端协议波动。

## 最终处理

### 启动状态与诊断

- 创建失败持续显示“本次启动未成功 / 尚未创建新运行”，不再展示旧运行进度。用户仍可主动选择历史记录。
- 快速协议没有候选筛选环节，首批异常正确定位到 formal_batch，不再误报 candidate_screening。
- 前后端保留明确的子任务错误码，区分模型服务、工具协议、输出截断和运行时不可用。

### 模型请求策略

- `scripts/configure_dsh_reasoning.mjs` 生成项目实例专用设置及 DSH patch，不修改全局模型配置；文件权限为 0600，凭据不进入提交内容。
- GLM 使用 thinking.type，DeepSeek V4 使用 thinking.type 和 reasoning_effort；声明 system 消息、max_tokens 字段，并省略不适合该路由的 strict/store 字段。DeepSeek 保持工具回合所需的 reasoning_content 传递。
- 在 preset 的 `agent/request` waterfall 上设置推理策略，作用于真实子 Agent，并进入原生 request/header：样本预测和样本审查在模型支持时选择 off，轮末评审优先 low，研究及提案保留默认或 high。
- off 仅关闭额外深思考；每个样本仍由 Agent 分析输入、选择工具或预测模型并提交自己的完整预测。输出 schema、工具授权和科学完整性要求继续执行。
- 模型请求约定纳入运行指纹，修改思考或工具协议参数后必须重新预检，避免沿用旧配置的成功回执。指纹不包含凭据或认证头。

### 故障恢复

- DSML 按已消费回合的最后一条 assistant 消息识别，之前出现真实 Skill 调用也不会掩盖错误。普通文本永不被当作工具执行或成功预测。
- 四角色预检每个角色最多 4 次、共享 120 秒和累计 30,000 reported tokens 阈值；单次输出最多 2,048 tokens。达到边界仍失败则不创建科学运行。
- sample.plan / sample.critic / sample.reflect 在原阶段绝对截止时间内允许一次新的真实协议调用。阶段内部仍最多两次，不无限循环。
- 阶段重试仍遇到 DSML 时，可信原生边界声明为可恢复的 provider 故障（503）。Host 保留成功样本和检查点，按退避重新推进；路由连续失败也触发冷却。纯错误码、旧 422 及无可信 provider 元数据的异常不能获得恢复资格。
- 新原生恢复链最多 12 次，且不超过 30 分钟。成功推进重置连续故障链；长期不可用仍停止并保留诊断。既有账本已经声明的重试次数不改写。
- 输出预算耗尽、schema 不合法、科学评测不完整等仍终止，不能通过重试策略变成成功样本。
- 研究合成返回“方案超过 24 KB 契约”时，快速小批量协议改用仅含冻结证据的宿主方案，并为每个候选槽位生成唯一的有界方向。该路径不调用备用网关、不伪造模型成功，下一阶段仍由 DSH Agent 生成真实候选变异。
- 原生工具协议错误保留显式 422 的失败闭环；无状态的控制器协议中断允许进入退避重试，避免把瞬时流中断误判为科学运行暂停。
